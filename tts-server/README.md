# 听书服务端

把小说朗读的合成放到你自己的另一台电脑上，手机/笔记本只负责播放。

为什么这么设计：好听的中文语音模型跑不动在手机上。之前试过在本机提前把整本书
合成成音频，代价是几个小时的等待和几个 GB 的 WAV，仍然不好听。而一台放在家里的
普通台式机完全跑得动——那就让它去跑，正文只发到你自己这台机器上，合成完播完即弃。

## 跑起来

那台电脑上装好 Python 3.10+，然后：

| 系统 | 命令 |
| --- | --- |
| Windows | 双击 `start.bat` |
| macOS / Linux | `./start.sh` |

首次启动会自动建虚拟环境、装依赖、下模型（几分钟，取决于网速）。跑完窗口里会打印
一行地址，形如：

```
  在 App 的「听书服务」里填这个地址：
      http://192.168.1.8:8880
```

把它填进 App 的「AI 引擎 → 听书服务」，打开「使用远程服务」，点「测试连接」。完事。

以后每次开机重复同一条命令即可，不会重新下载。

## 选后端

| 后端 | 命令 | 说明 |
| --- | --- | --- |
| `f5` （默认） | `start.bat` | F5-TTS。中文最自然，**支持音色克隆**，要显卡 |
| `kokoro` | `start.bat -Backend kokoro` | 82M 小模型，纯 CPU 也能跑，音质一般 |
| `edge` | `start.bat -Backend edge` | 微软在线语音，音质很好、不吃显卡，**但正文会发给微软** |

`edge` 是唯一一个会把文字发到外部的选项，所以它永远不是默认值，选它的时候服务端
会在窗口里明确提示一次。介意就用 `f5` 或 `kokoro`，那两个全程本地。

Linux/macOS 上写成 `./start.sh kokoro`。

## 分角色配音（f5 后端）

F5 的音色不是模型里固定的几个人，而是你给的一段参考录音。所以「给角色配音」就是往
`voices/` 里丢文件：

```
voices/
  旁白.wav      5–12 秒、干净、单人说话
  旁白.txt      这段录音里说的原话（可选，但准确率更高）
  主角.wav
  主角.txt
```

放好之后重新「测试连接」，App 的音色列表里就会出现「旁白」「主角」。
`voices/` 为空时用模型自带的默认参考音，服务端照样能跑。

录音来源随意：自己念一段、从有声书里截一段都行。只要你有权使用它。

## 换成别的服务端

这个服务端讲的是 OpenAI 的 `/v1/audio/speech` 协议，App 那边也只认这个协议。所以
你完全可以不用它，改用任何同样支持该协议的项目：

- kokoro-fastapi
- GPT-SoVITS（openai 兼容分支）
- Fish-Speech / OpenAudio
- index-tts
- openedai-speech

在 App 里填上它们的地址即可，不需要改 App。反过来，这个服务端也能被任何支持
OpenAI TTS 的软件使用。

## 接口

```
POST /v1/audio/speech    {input, voice, speed, response_format:"wav"} -> audio/wav
GET  /v1/audio/voices    -> {"voices":[{"id","label"}, …]}
GET  /v1/models
GET  /health
```

## 常见问题

**手机连不上** —— 两台设备要在同一个 Wi-Fi 下；Windows 防火墙首次会弹窗询问，选
「允许」；确认填的是 `http://` 而不是 `https://`。

**一直在缓冲** —— 没有显卡时 F5 合成一句要好几秒，改用 `kokoro` 或 `edge` 后端。

**只想局域网内可见** —— 默认就是这样：服务只监听内网地址，不做任何端口映射。要放到
公网请自己加反向代理和鉴权，并在 App 里填上密钥（服务端目前不校验密钥，仅透传）。
