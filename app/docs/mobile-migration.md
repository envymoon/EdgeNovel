# 移动端迁移基线

目标是让 Flutter 阅读界面、阅读数据和小说分析流程在 Windows、iOS、Android
之间共用，只把操作系统必须参与的部分留给各平台实现。

## 已建立的边界

- `platform_support.dart`：统一判断手机、桌面和紧凑/中等/展开布局。
- `desktop_book_drop.dart`：桌面拖入 TXT 的实现与书架隔离；手机只使用文件选择器。
- `ReaderState.setAiExecutionAllowed`：应用进入手机后台后暂停任务。未来只有在
  iOS/Android 原生调度器授予后台运行时间时才重新放行。
- Rust `LocalInferenceBackend`：章节摘要、人物分析、排雷、语义搜索继续使用原来的
  规则和提示词；Windows 走 `llama-server`，iOS 将在这里接入内嵌 llama.cpp。
- `model_manager.dart`：模型清单记录版本和 SHA-256。新文件校验通过后才替换当前
  模型，并保留一个旧版本用于恢复；校验或切换失败不会破坏正在使用的模型。
- `model_download.dart`：模型下载支持暂停、取消、断点续传、网络失败后继续；应用
  退出时保留未完成文件，取消时才清除。
- `reading_session_store.dart`：记录阅读页是否处于打开状态。应用重启后重新打开上次
  的书，具体章节、字节位置、标注和已读状态仍以数据库为准。

## 已完成的手机界面

- 书架在窄屏隐藏次要顶栏按钮，桌面拖放与手机导入分离。
- 书籍详情和设置页面使用手机全宽，在平板与桌面限制内容宽度。
- 阅读页适配底部安全区；极窄屏把标注和听书收入“更多”，目录和阅读助手保留直达。
- 模型与语义索引模型均按需下载，显示安装版本、校验状态、继续下载和旧版恢复入口。
- 320–390 宽度自动测试覆盖书架、设置、书籍操作、正文、章节目录、阅读助手和标注
  模式；测试发现的书架标签溢出已改为自动换行。

## 当前保持不变的内容

- Qwen3 0.6B Q8 和固定 8K 上下文。
- 人物图谱、感情结构、排雷、章节摘要与语义索引的算法。
- Windows 模型目录、后台任务断点和运行模式。
- Windows Release 的启动方式与文件导入方式。

## Windows 上继续完成

已经完成：

- 手机优先的书架、详情页、阅读页和设置页布局。
- 文件导入、应用存储、临时目录、设备状态、本地 TTS 和前后台许可的平台接口。
- 手机翻页的左/中/右点击区、左右滑动、滚动阅读、安全区和标注模式。
- 模型清单、按需下载、暂停、取消、断点续传、校验与版本回退。
- 阅读页、位置、标注、已读章节和 AI 队列的中断恢复。
- 手机窄屏核心流程的自动布局与交互测试。

继续完成：

1. 给 AI 任务增加操作系统真正授予的后台时间窗，不自行假设后台可持续运行。
2. 补齐未来微调模型的数据兼容版本和升级策略。
3. 获得可用移动设备后进行触控、内存、温度和耗电实测。

## 首次使用 Mac 时完成

1. 生成并固定 iOS Runner 工程、Bundle ID 与最低系统版本。
2. 编译 Rust `staticlib`，接入 iOS llama.cpp XCFramework 和 Metal。
3. 实现 `LocalInferenceBackend` 的内嵌版本，不修改上层分析流程。
4. 接入 iOS 文件导入、后台任务、温度/电量状态和系统 TTS。
5. 用真机验证 Q8 + 8K 的峰值内存、首字时间、发热、耗电及恢复能力。
6. 建立 TestFlight 构建和崩溃日志流程。

目前不在 Windows 上手工生成 `ios/`。原生工程需要 Xcode 验证，过早生成只会产生
无法编译确认的配置；共用代码不依赖它，可以先持续推进。
