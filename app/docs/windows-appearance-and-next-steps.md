# Windows 外观与后续减负方向

2026-09-04。本轮只构建 Windows；不启动模型或模拟器，不发布新版本。

验证：25 项 Flutter 测试通过、6 项 Rust 非模型测试通过（6 项模型测试保持忽略）、单章缓存隔离测试通过；Dart 静态检查通过。最终 Windows Release 构建完成，产物仍位于 `app/build/windows/x64/runner/Release/novel.exe`，分发目录的 Rust DLL 与最新编译输出哈希一致。未启动实际应用，字体观感和任务运行需后续人工确认。

## 本轮界面

- Windows 显示名称与持久化产品名均恢复为 novel；界面内仍按语言显示“小说阅读器 / Novel Reader”。这些名称不得再与品牌美术一起改动，以保持原书架、模型和设置目录不变。
- 设置 → 外观：界面字体、统一字重、背景和强调色。
- Windows 默认界面字体指定为微软雅黑；宋体、楷体、Segoe UI 可选，也可使用原字体管理器下载或导入 TTF/OTF。系统缺失的字形会回退，特殊字体不保证覆盖全部中文字。
- 界面与正文分别保存字体。正文的排版测量和实际绘制均使用独立字体，避免更换菜单字体后分页错位。
- 统一界面字重默认开启，应用自己的菜单与标题使用常规字重；关闭后保留温和的粗细层次。字体预览与正文不参与统一。
- 新增雾青、暮紫、深海三套背景，五种强调色；使用普通颜色绘制，不增加持续动画、模糊或纹理。
- 书架显示最近停留章节以及该章已有的 AI 简介，最多两行。缺少介绍时不生成、不替用其他章节；未阅读的书不显示该提示。数据层单章查询，不搬运全书概览。

## 模型减负：建议，不是已实现的收益

现有实现已经有限线程、提示词处理线程上限、低优先级、关闭忙轮询、单任务槽、章节间休息、设备条件调度与空闲卸载。主模型保持 Q8 权重、Q8 KV 和 8K 上下文；兼容回退仍可能使用 F16 KV。

1. **测量低负载模式的峰值**：同时记录进程内存、显存、耗电、温度及界面响应。桌面 2GB 显存能运行不等同于手机 2GB 总内存可用；也不能据此承诺某档手机。
2. **更小的提示词微批次**：分别测试 256/128/64 的物理批次，目标是减少中间计算缓冲和单次峰值；上下文仍是 8192，不删片段。不同批次可能带来数值差异，须复用人物/排雷/总结回归集并多次重复。
3. **减少重复执行**：审计所有生成结果缓存的键和失效条件。精确包含原文、提示词版本、模型指纹和生成参数；只复用已完成、验证过的同一请求。用户要求重做、原文变化、模型更换时失效。已有章节缓存继续复用，不把现有能力算成新增优化。
4. **错开检索模型与生成模型驻留**：在低内存模式按任务阶段卸载暂时不用的模型，测量能否减少双模型及各自缓冲同时存在的峰值；评估反复加载带来的耗电与等待。不要只按小模型文件大小估算收益。
5. **更细的让步调度**：先测现有章节间休息能否满足体验，再试请求内部的分段让步或自适应占空比。必须保留 KV 状态、不截断回答；目标是降低短时抢占和发热，不保证总能耗下降。
6. **固定提示词前缀复用**：可减少预填充工作，但缓存可能增加驻留内存；不同处理路径也可能影响数值结果，排在纯结果复用之后实验。

保留基线与开关，一次只改一项。质量仍以是否遗漏关键证据、错误人物/关系、无依据断言和格式失败为主；速度只作记录。不能在未实测前承诺“完全无感”或具体节省百分比。

## 更值得增加的阅读能力

- **资料备份与恢复**：书籍位置、标注、分类、设置、已有分析结果可一起导出；以后换机也有基础。恢复须验证文件版本和书籍身份。
- **临时跳转返回**：查人物原文、搜索、目录跳转之后，一次回到出发位置。保留最近停留章节与已读状态各自语义，不用最远章节代替实际位置。
- **原文勘误与显示替换**：对乱码、固定广告或错字做可撤销的显示层修正，原始文件不变。
- **人物别名人工纠正**：用户确认同一人物或错误关系后保存纠正结果，重新生成时仍尊重这些纠正。比让小模型反复猜测更可控。
- **标注检索和个人摘录**：先做全文搜索、分类与导出；如需 AI，只对用户选中的少量标注生成短标题或分组建议，原文始终可见。

不建议当前重新扩展成全书开放式聊天或完全自动的口味推断；此前 0.6B 实验已说明其可靠性边界。新增 AI 能力宜围绕已有原文、既有章节概览与人工确认的数据展开。
