# 本地模型减负实验清单（暂不实施）

状态：冻结。完成静态界面美术调整后保留为下一阶段实验入口；在用户明确指令前，不修改当前稳定推理引擎、不运行模型。

## 固定基线

- 模型权重：Q8
- KV Cache：Q8
- 上下文：8192，不降低
- 引擎：当前已验证的 llama.cpp b9957
- 首要判定：现有功能表现不能明显下降，不能增加幻觉
- 速度只记录，不作为淘汰方案的主指标

## 待逐项验证

1. **降低物理微批次**
   - 分别测试 `ubatch = 256 / 128 / 64`。
   - 目标：降低单次内存和计算峰值，允许总耗时增加。
   - 风险：吞吐降低；仍须对全部核心功能做结果回归。

2. **检索模型与生成模型互斥驻留**
   - 任一时刻只保留当前任务需要的模型。
   - 目标：避免两套模型同时占用内存。
   - 风险：模型切换会增加等待、磁盘读取与短时能耗；高频交替可能得不偿失。

3. **复用固定提示词前缀和已验证结果**
   - 单独验证 llama.cpp 的提示词缓存/前缀复用，并复用输入与配置完全一致的已验证结果。
   - 目标：减少重复预填充。
   - 风险：缓存失效规则错误可能串入旧上下文；必须把模型版本、提示词版本、采样参数和输入摘要纳入缓存键。

4. **关闭启动预热**
   - 与当前预热方式做 A/B 对照。
   - 目标：降低应用或引擎启动时的瞬时负载。
   - 风险：第一次 AI 任务更慢，首次任务的峰值可能只是被延后而非消失。

5. **新版 `mmap + lazy-mode` 隔离测试**
   - 在独立引擎副本中验证，不覆盖当前稳定引擎。
   - 目标：观察模型加载、驻留内存和首次推理峰值是否改善。
   - 风险：平台和存储介质差异大；0.6B 模型收益可能有限；新版引擎可能带来结果或兼容性变化。

## 实验纪律

- 每项和组合都从同一基线分支开始，不把未验证的变量叠进正式版本。
- 使用固定书目、固定章节、固定提示词、固定随机参数；每个配置至少重复运行三次。
- 核心回归覆盖：章节概览、人物图谱、感情结构、排雷候选、语义检索。
- 记录峰值内存、显存/共享内存、CPU/GPU 峰值与均值、能耗、温度、首任务等待和总耗时。
- 出现明显漏检、错判、输出结构损坏或新增幻觉，直接标记为不可迁移，即使资源数据更好。

## 最终交付形式

实验完成后提供一张 tradeoff 图和明细表：横向比较资源收益，纵向标注质量风险；同时列出每项的负面效果、适合设备档位，以及是否建议进入 Windows 和移动端正式版本。
